## 1. 已定案的決策

| 項目 | 決定 | 理由 |
|---|---|---|
| 平台 | **網頁 + PWA** | 平板、手機、電腦都能玩，可以加到主畫面、離線玩，不必上架 App Store |
| 第一版模式 | **與 AI 對戰（六檔棋力）** | 同裝置雙人、線上雙人留到之後 |
| 美術 | **程式繪製的 Q 版 SVG 動物** | 原型已確認；風格一致、檔案小、身體部位可以分開動 |
| 動畫 | 每隻動物有專屬待機動作，加上共用的事件動畫 | 讓棋盤活潑，取代參考網站的純文字棋子 |

## 2. 技術選型

| 層 | 技術 | 說明 |
|---|---|---|
| 語言 | TypeScript | 規則邏輯多，型別可以減少錯誤 |
| 建置 | Vite | 開發伺服器快，設定少 |
| 畫面 | React | 元件化，動物、棋盤、對話框各自獨立 |
| 動畫 | Motion（原 Framer Motion）＋ CSS keyframes | 一次性動作（移動、跳河、吃子）用 Motion；持續循環的待機動作用 CSS |
| 狀態管理 | Zustand | 輕量，容易做悔棋／重做 |
| AI | Web Worker | 在背景執行緒計算，動畫不會卡 |
| PWA | vite-plugin-pwa | 離線快取、加到主畫面 |
| 測試 | Vitest | 規則引擎與 AI 的單元測試 |

## 3. 系統分層

```mermaid
flowchart TD
  UI["畫面層（React）<br/>棋盤、動物、對話框、設定"] -->|玩家點擊| Session
  Session["對局層（Zustand store）<br/>回合、悔棋／重做、棋譜、重複局面計數"] -->|走一步| Engine
  Engine["規則引擎（純 TypeScript）<br/>合法走法、吃子、勝負判定"] -->|事件清單| Session
  Session -->|事件清單| Director["動畫導演<br/>依序播放事件動畫"]
  Director --> UI
  Session -->|輪到 AI| Worker["AI（Web Worker）<br/>Alpha-Beta 搜尋"]
  Worker -->|選好的走法| Session
  Worker -.->|使用| Engine
```

**原則：**

1. **規則引擎完全不碰畫面**，只輸入盤面、輸出結果，可以單獨測試。AI 也直接呼叫同一套引擎，保證 AI 和玩家遵守相同規則。
2. **動畫由事件驅動**：引擎每走一步回傳一串事件，動畫導演照順序播放；播完才開放下一步操作。玩家和 AI 走棋用同一條流程。
3. **動物外觀包成單一元件**：`<Animal type side state face />`。之後要換美術（例如改用 Rive），只要換這個元件。

## 5. 規則引擎

### 5.1 資料結構

- 座標：`{ row: 0–8, col: 0–6 }`，第 0 列是藍方底線、第 8 列是紅方底線。對外顯示用 `a1`～`g9`（紅方在下）。
- 盤面：9 × 7 陣列，每格放 `Piece | null`；`Piece = { type, side, id }`。
- `side`：`'red' | 'blue'`。
- 地形固定，不存在盤面裡，由 `board.ts` 的函式查詢（`isWater`、`trapOwner`、`denOwner`）。

### 5.2 走一步的輸出：事件

```ts
type GameEvent =
  | { kind: 'move'; pieceId: string; from: Pos; to: Pos }
  | { kind: 'jump'; pieceId: string; from: Pos; to: Pos }           // 獅、虎跳河
  | { kind: 'enterWater'; pieceId: string; at: Pos }
  | { kind: 'leaveWater'; pieceId: string; at: Pos }
  | { kind: 'capture'; pieceId: string; victimId: string; at: Pos }
  | { kind: 'enterTrap'; pieceId: string; at: Pos }                 // 進入敵方陷阱
  | { kind: 'leaveTrap'; pieceId: string; at: Pos }
  | { kind: 'gameOver'; winner: Side | null; reason: 'den' | 'allCaptured' | 'noMoves' | 'repetition' };
```

### 5.3 不合法走法的原因

點了不能走的格子時，引擎回傳原因，畫面再轉成兒童語氣的提示：

| 原因代碼 | 情境 | 提示範例 |
|---|---|---|
| `notAdjacent` | 不是上下左右一格 | 一次只能走上下左右一格喔！ |
| `ownPiece` | 目標有己方動物 | （改成選取那隻動物） |
| `ownDen` | 想進己方獸穴 | 那是自己的家（獸穴），自己人不能進去喔！ |
| `waterOnlyRat` | 非鼠想下水 | 只有老鼠會游泳喔！ |
| `bankCapture` | 跨水陸吃子 | 老鼠在水裡，不能咬岸上的動物喔！ |
| `jumpBlocked` | 跳河路徑有鼠 | 河裡有老鼠擋住，獅子跳不過去！ |
| `rankTooLow` | 等級不夠 | 貓咪比獅子小，吃不掉牠！ |
| `elephantVsRat` | 象想吃鼠 | 大象怕老鼠，不敢吃牠！ |
| `noPiece` | 起點沒有動物 | 先點一隻動物喔！ |
| `offBoard` | 目標在棋盤外 | （畫面不會發生） |
| `notYourTurn` | 動了對方的動物 | 現在輪到另一邊喔！ |
| `gameOver` | 對局已經結束 | （畫面不會發生） |

### 5.4 對外介面

| 函式 | 用途 |
|---|---|
| `createGame(board?, turn?)` | 開新局，預設初始盤面、紅方先走 |
| `play(state, from, to)` | 輪到的一方走一步；成功回傳新的 `state`、`move`、`events`，失敗回傳原因。`state` 不可變，悔棋只要保留舊的 `state` |
| `checkMove(board, from, to)` | 只檢查一步合不合法（不管輪到誰），點錯格子時拿原因 |
| `movesFrom(board, from)` | 一隻動物的所有合法走法，畫腳印用 |
| `legalMoves(board, side)` | 一方的所有合法走法，AI 用 |
| `positionKey(board, turn)`、`repetitionCount(state)` | 重複局面判斷 |

勝負判定順序：進入敵方獸穴 → 吃光對方 → 對方無合法走法 → 第三次重複局面。

### 5.5 測試

[01-game-rules.md](../evaluation/01-game-rules.md) 第 7 節的 15 項檢查清單，每一項都要有對應的單元測試。另外補上初始盤面座標、三次重複判和、無合法走法判負的測試。

## 6. AI

- **演算法**（`ai/search.ts`）：迭代加深的 Negamax ＋ Alpha-Beta 剪枝，搭配置換表（Zobrist 雜湊）、走法排序與吃子延伸（quiescence）；時間到就用上一層的完整結果，深度 1 一定搜完。走法產生直接呼叫規則引擎，只是在同一份盤面上走／退而不複製。
- **重複局面**：把對局中出現過的局面接進搜尋，會造成第三次重複的走法評為和棋（0 分）。
- **評估函式**：子力價值（鼠 125、貓 190、狗 245、狼 310、豹 385、虎 510、獅 560、象 590）、往前每列 10 分、靠中路每欄 3 分、靠近敵方獸穴加分（距離 3 格內）、站在敵方陷阱扣 150 分。機動力沒有採用（成本高、效果小）。
- **走法排序**：置換表的最佳步 → 進敵方獸穴 → 吃子（被吃子價值高、攻擊子價值低的優先）→ 往前、跳河加分，走進敵方陷阱扣分。
- **隨機擾動**：有擾動的難度，根節點每一步都用完整視窗算出精確分數，前 4 名各加上 ±擾動÷2 再重新排序。
- **六檔難度**（`ai/levels.ts`）：

| 難度 | 搜尋深度 | 每步時間上限 | 隨機擾動 | 兒童調整 |
|---|---|---|---|---|
| 入門 | 1 | 20 ms | 110 | 不做吃子延伸（看不到對方會反擊）；三成機率漏看吃子 |
| 簡單 | 1 | 50 ms | 60 | 有吃子延伸（不會白白送子）；一成五機率漏看吃子 |
| 中等 | 3 | 100 ms | 12 | — |
| 困難 | 4 | 250 ms | 0 | — |
| 高手 | 5 | 500 ms | 0 | — |
| 大師 | 6 | 1000 ms | 0 | — |

  簡單原本規劃深度 2，但自我對弈時「像小朋友的玩家」40 盤只贏 0～1 盤，所以改成深度 1 加吃子延伸。
- **一律**：能直接進獸穴就進（讓對局能結束）。
- **自我對弈結果**（`npm run ai:selfplay`，2026-10-18）：
  - 六檔都能下完一盤。電腦上最慢一步：大師約 300 ms、高手約 200 ms，都在時間上限內。
  - 相鄰兩檔各下 6 盤（開局先隨機走 4 步）：多數是上一檔勝，但高手 vs 困難只有 2 勝 3 敗 1 和，兩檔的差距不明顯。
  - 「像小朋友的玩家」（能進穴就進、七成機會吃子、其他時候隨機但偏好往前）：贏入門約 55～70%、贏簡單約 25%。
- **AI 思考時的表現**：AI 至少「想」0.5 秒再走，AI 方的動物東張西望（`data-state="thinking"`），對話框顯示「電腦想一想…」。
- **悔棋**：和電腦下時退回上一次輪到玩家的時候（通常退兩步）；AI 還在想時也可以悔棋，算到一半的結果會作廢。重做留到之後。
- **對手與難度**：在開局設定視窗選（見第 8 節）；M3 時放在畫面下方的下拉選單已移除，對局中要換就按「新的一局」。

## 7. 動畫

### 7.1 元件結構

每隻動物由外到內分成五層，各層負責不同的動畫，互不干擾（原型已驗證）：

| 層 | 負責 |
|---|---|
| piece | 在棋盤上的位置（CSS 變數 `--r`、`--c`）；內層 travel 播格與格之間的移動 |
| hop | 跳躍的高度弧線 |
| lift | 被選中時浮起 |
| act | 一次性動作：壓扁伸展、搖頭、被吃掉縮小 |
| bob | 持續循環：呼吸、發抖、游泳、歡呼 |

**一步棋的播放流程**（`animation/director.ts`）：引擎回傳事件後，store 先同步把畫面換成新盤面（棋子已在新格），導演再從舊位置的偏移量播回原點，所以動畫結束時不會跳格。被吃的動物暫時留在畫面上（ghost），播完被吃動畫才移除；剛下水的老鼠落地後才顯示泡在水裡。播放期間 `busy`，不接受點擊。

### 7.2 表情與狀態

- **表情**（face）：一般、開心、害怕、被吃（眼睛變 > <）。
- **狀態**（state）：待機、被選中、在敵方陷阱（害怕）、歡呼。
- **眨眼**：每隻動物每 2～6 秒隨機眨一次。

### 7.3 每隻動物的待機動作

| 動物 | 待機動作 | 已實作 |
|---|---|---|
| 象 | 甩鼻子、耳朵搧動 | ✅ |
| 獅 | 鬃毛蓬鬆擺動 | ✅ |
| 虎 | 尾巴擺動 | ✅ |
| 豹 | 舔爪子 | ✅ |
| 狼 | 豎耳朵、仰頭 | ✅ |
| 狗 | 搖尾巴、吐舌頭、耳朵晃動 | ✅ |
| 貓 | 甩尾巴、耳朵抖動、鬍鬚 | ✅ |
| 鼠 | 鼻子嗅嗅、鬍鬚抖動、耳朵 | ✅ |

### 7.4 事件動畫與時間（原型的數值）

| 事件 | 動畫 | 時間 |
|---|---|---|
| 移動 | 蹦跳一格，起跳與落地壓扁伸展 | 400 ms |
| 跳河 | 拋物線大跳、身體傾斜、落地揚起塵土 | 760 ms |
| 下水／上岸 | 濺起水花；在水裡下半身沉入水中、左右划水 | 水花約 0.6～0.9 秒 |
| 吃子 | 攻擊方撲過去；移動到 60% 時被吃方縮小旋轉、迸出星星與「噗！」 | 被吃 460 ms |
| 進入敵方陷阱 | 持續發抖、冒汗，等級數字變 0 | 持續 |
| 不能走 | 搖頭 | 560 ms |
| 進入獸穴 | 歡呼跳躍、灑彩帶，之後顯示勝利畫面 | 約 0.9 秒後顯示 |

### 7.5 無障礙

- 支援系統的「減少動態效果」設定，遊戲內也有開關：關閉待機循環與粒子特效，移動改為直接到位。
- 紅方用實線外框、藍方用珠子外框，色盲也分得出來。
- 每隻動物右下角顯示等級數字，不識字的小朋友也能比大小。
- 格子是可聚焦的按鈕，支援鍵盤操作。

## 8. 開局設定、PWA、版面（M4）

### 8.1 開局設定

- 一打開遊戲、按「新的一局」、結果卡片的「換設定」都會跳出設定視窗；結果卡片的「再玩一次」直接用同樣設定開新局。
- 選項：對手（電腦／兩個人輪流）、難度（六檔，用星星數表示，不識字也看得懂）、你要當（紅方／藍方）、誰先走（你先／電腦先；兩人輪流時是紅方先／藍方先）。預設：電腦、入門、紅方、你先。
- 設定和「減少動態效果」開關存在 `localStorage`（`jungle-chess:settings`、`jungle-chess:reduce-motion`），下次打開沿用；存不了（無痕模式）就每次用預設值。讀到壞掉或不認得的欄位就改用預設值。
- 對局中打開設定視窗時電腦先停下來；按「回到棋盤」（或 Esc）繼續，按「開始！」就開新局。剛打開遊戲還沒開始時沒有「回到棋盤」。
- 悔棋：和電腦下時要退得回「輪到玩家」的局面才能按，所以電腦先走的第一步之後還不能悔棋。

### 8.2 棋盤顛倒

和電腦下、玩家執藍方時，棋盤整個轉 180 度，玩家的動物一律在下方。引擎座標不變，只有畫面換算（`registry.ts` 的 `toView`）：格子依畫面順序排列（鍵盤 Tab 順序也跟著變），棋子、腳印、選取光暈、特效位置與移動動畫的方向都經過同一個換算。兩人輪流時不顛倒（紅方在下）。

### 8.3 PWA

- `vite-plugin-pwa`（generateSW）：預先快取所有程式、樣式、圖示與 AI 的 Worker，第一次連網打開後就能離線玩。
- Google Fonts 的字型在第一次連網使用時存進快取（CSS 用 StaleWhileRevalidate、字型檔用 CacheFirst）；還沒存到時離線會改用系統字型。
- 更新方式 `autoUpdate`：新版的 service worker 裝好就接手，但**不會自動重新整理**（避免小朋友下到一半畫面被重整），下次打開才換成新版。
- `base: './'`：放在網域根目錄或子路徑都能用。**要加到主畫面、離線玩，網站必須是 HTTPS**（`localhost` 除外），用區網 IP 開發伺服器在平板上測不到離線。
- 圖示：`public/icon.svg`（黃底咖啡色腳印，滿版、可裁成圓形）→ `npm run icons` 產生 64／192／512、maskable 512、蘋果 180 與 favicon.ico。

### 8.4 版面

- 直式（手機、平板直放）：單欄；格子大小取「螢幕寬 ÷ 7」和「(螢幕高 − 236px) ÷ 9」的較小值，介於 32～88 px。
- 橫式（寬高比 ≥ 6:5，平板橫放、手機橫放、電腦）：棋盤在左、用滿整個高度，標題、對話框、按鈕、圖例在右邊一欄；對話框的尖角改指向左邊。
- 很矮的橫式螢幕（高 ≤ 520px）：設定視窗改成左右兩欄、拿掉動物圖示，手機橫放也放得下。
- 觸控：取消雙擊放大、整頁回彈，棋盤上不會選到文字；按鈕高度至少 44 px；考慮瀏海與底部橫條的安全區域。
- 自我檢查（無頭 Edge，2026-10-18）：390×844、375×667、768×1024、1024×768、844×390、667×375 都沒有橫向捲動；離線重新整理後可以開局，電腦照常下棋。
