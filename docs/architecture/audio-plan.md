## 1. 設計方向

採用「玩具森林」風格：柔和木琴、木頭敲擊、彈跳與水滴，搭配短促、友善的卡通動物叫聲。音效幫助小朋友理解選取、走棋、地形與結果，同時讓棋子有個性。

- 一次操作有清楚的主要聲音；一般動作約 0.1～0.4 秒，結算旋律不超過 2 秒。
- 吃子像玩具消失的「噗」，不使用咬碎、痛叫或猛烈撞擊聲。
- 不能走時用柔和提醒，搭配既有原因文字，不使用尖銳警報或責備語音。
- 待機、眨眼、搖尾巴、陷阱發抖與 AI 思考保持安靜。
- 音效是輔助，所有規則、輪到誰及勝負資訊仍有視覺提示。
- 第一階段聚焦操作音效；第二階段加入動物叫聲。背景音樂的獨立試作已試聽通過，遊戲整合另行安排；森林環境音與語音教學仍列後續評估，避免掩蓋走棋回饋。

## 2. 核心音效清單

每個 ID 先製作一個版本；長度指音檔本身，不代表延長操作或動畫時間。

| ID | 情境／聲音設計 | 建議長度 | 觸發時機 |
|---|---|---|---|
| `ui.tap` | 一般按鈕，輕木片「嗒」 | 60～100 ms | 按鈕操作成功；棋盤不套用通用點擊聲 |
| `piece.select` | 選取動物，柔和上揚「啵」 | 100～160 ms | 成功選取或改選；取消選取保持安靜 |
| `piece.land` | 普通陸地走棋，圓潤木頭「咚」 | 100～180 ms | 移動落地；有吃子、入水或陷阱提示時讓位 |
| `piece.jump` | 獅虎跳河，輕巧滑音「咻」 | 200～350 ms | 起跳；落地沿用 `piece.land`，吃子時省略落地聲 |
| `water.enter` | 老鼠下水，小水花「撲通」 | 200～350 ms | 入水水花出現 |
| `water.exit` | 老鼠上岸，輕水滴「啪啦」 | 150～250 ms | 離水水花出現；省略普通落地聲 |
| `water.step` | 老鼠水中走一格，短划水聲 | 120～220 ms | 水中移動完成；水中吃子時讓位 |
| `piece.capture` | 吃子，氣泡「噗」加柔和亮音 | 200～350 ms | 被吃棋子的星星與「噗！」出現，只播一次 |
| `trap.enter` | 進敵方陷阱，兩個短促下行木琴音 | 200～350 ms | 移動完成、陷阱狀態可見後；不循環 |
| `trap.leave` | 離開敵方陷阱，輕快上揚音 | 150～250 ms | 移動完成；吃子或結算時讓位 |
| `move.invalid` | 無效操作，柔和「嘟啵」 | 120～220 ms | 顯示不能走／輪到別人的提示時 |
| `game.start` | 新局開始，三音木琴 | 400～650 ms | 使用者開始／重新開始成功，取代按鈕聲 |
| `game.win` | 勝利，明亮短旋律 | 1.2～1.8 s | 最後一步完成、開始慶祝時 |
| `game.encourage` | 對 AI 落敗，溫暖收尾旋律 | 0.8～1.2 s | 最後一步完成、結算時 |
| `game.draw` | 和棋，平穩收束的三音旋律 | 0.7～1.0 s | 三次重複局面結算時 |

第一階段共 **15 個核心音效**。目前是可手動操作雙方的對局流程，任一方獲勝均播放 `game.win`；接上 AI 模式、確定人類玩家陣營後，才依玩家視角區分勝利與鼓勵音。進獸穴、吃光及無合法走法共用結算音，以畫面文字說明勝因。

## 3. 八隻動物的個性叫聲

第二階段每種動物先製作一個 0.25～0.6 秒的短聲；屬於卡通角色演出，不定位為真實動物聲音教材。

| 動物 | 聲音方向 |
|---|---|
| 象 | 圓潤短鼻鳴「噗嗚」，減弱刺耳高頻 |
| 獅 | 溫和、有胸腔感的小「嗷」 |
| 虎 | 短而有彈性的「嗷嗚」，與獅子做節奏區別 |
| 豹 | 輕巧低聲「嗚嚕」，比虎更短 |
| 狼 | 柔和上揚「嗚～」，不做悠長嚎叫 |
| 狗 | 一聲友善短「汪」 |
| 貓 | 輕柔短「喵」 |
| 鼠 | 圓潤「吱啾」，避開刺耳尖叫 |

叫聲只在玩家成功選取時播放，並取代該次 `piece.select`。同一物種冷卻 3 秒，全體叫聲間隔至少 1 秒；冷卻中仍可播放節流後的普通選取聲。快速改選時停止上一隻叫聲，走棋開始時短淡出叫聲，讓動作聲清楚。AI 行動不額外播放選取叫聲。

## 4. 聲音密度與事件組合

- `ui.tap`、`piece.select` 最短間隔 120 ms；`move.invalid` 最短間隔 700 ms。被 `busy` 阻擋的點擊不發聲。
- 同時最多 3 個聲音，動物叫聲最多 1 個；超出時丟棄或淡出低優先聲，不排隊延後補播。
- 搶占優先順序：結算 ＞ 吃子／入陷阱／水花 ＞ 移動 ＞ 選取／按鈕／叫聲。
- 同一步若吃子又進敵方陷阱，先播吃子，再於陷阱狀態提示時播較輕的陷阱聲；不加入普通落地聲。
- 同一步出現結算，保留已發生的動作聲，動作結束後播一次結算；省略尚未播放的離陷阱等次要提示。結果卡片出現時不再播一次。
- 普通陸地走棋：選取 → 落地。跳河吃子：選取 → 起跳 → 吃子 → 必要的結算。
- 老鼠入水／出水以各自水花聲取代落地；水中走棋用划水聲；水中吃子用吃子聲。
- 未來悔棋只播一次輕按鈕聲，取消原回合待播聲；不倒放吃子、動物或結算音。棋譜重播預設靜音。

## 5. 與目前程式的接合

現有接點為 `src/session/store.ts` 的選取、無效走法、新局及 `finish()`，以及 `src/animation/director.ts` 的 `playMove()`、`travel()`、`poof()`。事件沿用 `src/engine/events.ts`，不讓規則引擎或未來 AI 搜尋呼叫播放器。

建議新增以下模組（均為規劃路徑）：

| 路徑 | 責任 |
|---|---|
| `src/audio/manager.ts` | 單一 AudioContext、解碼快取、音量、靜音、聲道上限、停止播放 |
| `src/audio/manifest.ts` | 音效 ID、檔案路徑、分類、增益與冷卻時間 |
| `src/audio/cues.ts` | 每步事件的聲音取捨、優先順序與去重 |
| `src/audio/settings.ts` | 音效／叫聲偏好及本機儲存 |
| `public/audio/sfx/`、`public/audio/animals/` | 核心音效與角色叫聲 |

使用原生 Web Audio API 播短音效，先不增加音訊套件。資源管理獨立於 React render；只在實際操作與動畫節點發出播放命令，避免重渲染造成重複音效。

**同步方式：** 普通移動目前約 400 ms、跳河約 760 ms；使用實際起跳、落地、水花與吃子特效節點觸發，不在音效層重寫一套毫秒排程。現有吃子在移動 60% 後還有 `poofDelay` 與縮小動畫延遲，因此「移動 60%」不是星星出現時間，吃子聲應接在 `poof()` 產生星星的同一節點。

**減少動態效果：** 保留音效偏好，與減少動畫分開設定。精簡動畫時直接依狀態完成觸發主要音效，省略跳躍滑音與一般落地，保留吃子、水花、陷阱及結算；不等原本動畫時間，也不把整串聲音同時擠出。

**中斷與失敗：** 每局、每步使用識別碼管理待播工作；重新開始、未來悔棋、離開頁面及切到背景時，取消延後回呼並停止對應音源。不能只清除音源，還要阻止舊回呼重新發聲。音檔下載、解碼或播放失敗均略過該聲音，不能阻止走棋、解除 `busy` 或結算。

## 6. 設定與瀏覽器行為

- 主畫面提供明顯的「聲音開／關」按鈕；設定提供音效音量與獨立「動物叫聲」開關。主靜音涵蓋所有聲音。
- 建議初始音量 50%，動物叫聲開啟；記住使用者偏好，重新開始不重設。儲存不可用時保留本次使用設定即可。
- 初次載入不發聲；在第一次點擊／觸控或鍵盤操作時建立或恢復 AudioContext。未解鎖、仍在載入的舊音效直接略過，不事後補播。
- 音量調整結束可播放一聲短預覽；關閉音效立即短淡出所有聲音並清空待播工作，關閉操作本身不發聲。
- 分頁隱藏時暫停聲音；回前景不補播歷史音效，必要時由下一次手勢恢復 AudioContext。
- 手機 Safari、Android Chrome 及 PWA 模式需實機確認；音效功能不以允許自動播放為前提。

## 7. 音檔製作與交付

先製作「落地、吃子、入水、無效走法、勝利」五個代表樣本，搭配現有動畫試聽，確認整體風格後再完成全套。

- 核心音效可用合成與簡單擬音製作；動物聲建議使用同一演出／處理風格的錄音或授權素材。
- 保留 48 kHz WAV 母檔；網頁先提供 MP3（44.1／48 kHz，約 96～128 kbps），短音效以單聲道為主，必要時再加替代格式。
- 去除多餘前置靜音、頭尾短淡入淡出，控制各音檔感知音量；混音保留餘裕，以最多 3 聲疊播測試不破音。
- 檔名使用穩定 ID 與版本，例如 `piece-land-v1.mp3`；清單記錄來源、作者、授權、修改與署名方式。採可散布於遊戲的素材，需署名者附於遊戲致謝。
- 初始傳輸目標：15 個核心音檔合計不超過 500 KB，8 個動物叫聲合計不超過 500 KB；屬預算，製作後量測調整。
- 核心組先載入，角色組可延後載入。待 PWA 階段接上離線快取及版本更新；首次成功快取完成後才承諾離線音效可用。

## 8. 實作順序與驗收

| 階段 | 工作 | 完成條件 |
|---|---|---|
| A：風格試聽 | 5 個代表樣本與動畫配對 | 手機喇叭與耳機都清楚、柔和，小朋友能分辨落地／吃子／提醒 |
| B：核心音效 | 15 音、播放器、靜音／音量、事件同步與中斷 | 下列核心情境通過，音效失敗不影響對局 |
| C：角色個性 | 8 種叫聲、叫聲開關與冷卻 | 快速切換棋子不疊成一片；連玩一盤不覺得吵 |
| D：後續整合 | AI 勝負視角、悔棋、PWA 快取 | 隨對應功能驗收，不把尚未完成的模式當成現有能力 |

驗收情境：

1. 普通移動、獅虎橫／縱跳、跳河吃子、鼠入水／出水／水中移動／水中吃子，音畫同步且無多餘落地聲。
2. 進出敵方陷阱有一次提示；己方陷阱無降級提示；吃子兼入陷阱的聲音順序清楚。
3. 三種勝利原因與三次重複和棋各結算一次；未來 AI 模式依人類陣營選擇勝利／鼓勵音。
4. 快速連點無效走法、改選及按鈕，符合冷卻與聲道上限；滑鼠、觸控、鍵盤操作一致。
5. 普通／減少動態效果兩種模式皆有正確主要音效，靜音仍可理解全部操作與結果。
6. 播放中靜音、重新開始、切背景，再返回時無舊音效殘留；未來悔棋也適用。
7. 音檔 404、解碼失敗、網路慢、AudioContext 未解鎖或被暫停，仍可完成對局。
8. 偏好重載後保留；PWA 完成整合後驗證已快取版本在離線狀態可播放。

自動化測試集中於事件取捨、單次結算、冷卻、取消及載入失敗不阻塞對局；音色、感知音量與音畫同步以實機試聽驗收。
